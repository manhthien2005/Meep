🎨 Figma → Flutter — FE-first workflow
Bước cụ thể để chuyển thiết kế Figma thành Flutter widget trong module của mình.
  • 1
    Mở Figma, tìm frame cần implement
    Xem comment trong stub file để biết frame nào — ví dụ: // TODO(P/T6/TBD): implement ProfileScreen per Figma — 572:4183 → số 572:4183 là ID frame trên Figma.
  • 2
    Chạy /figma-to-flutter trong Claude Code
    Claude đọc frame từ Figma (qua MCP đã setup), tạo Flutter widget vào đúng file presentation/ của module.
  • 3
    Review output — thay thế hardcode bằng token
    Claude có thể tạo ra màu/font hardcode. Phải đổi sang theme token: 
    // ❌ Hardcode → CI sẽ reject
color: Color(0xFF1f2328),
style: TextStyle(fontSize: 16, fontWeight: FontWeight.bold),

// ✅ Dùng token
color: AppColors.textPrimary,
style: AppTextStyles.bodyMedium,
  • 4
    Wire vào stub provider để thấy data thật
    Dùng FakeRepository với typed data để kiểm tra UI trông đúng không. Không dùng text cứng như "Thien PDM".
  • 5
    Chạy flutter analyze — phải sạch trước khi commit
    Nếu còn lỗi → fix hết rồi mới commit. Đừng để lỗi tích lũy.
⚠️ Nếu Figma dùng màu/font chưa có trong AppColors / AppTextStyles → không tự thêm vào theme. Ping leader, chờ designer approve token mới.

✅ Definition of Done — Xong là xong thật ▼

Task chỉ được mark Done khi đủ 7 điều kiện. Thiếu 1 → chưa xong.

  1. Code commit đúng Conventional Commits + mô tả tiếng Việt
  2. Có test — unit test cho logic, widget test cho UI quan trọng
  3. flutter analyze + dart format clean, 0 errors
  4. PR mở đúng template, có Closes #N
  5. ≥ 1 leader (manhthien2005) approve trên GitHub
  6. CI pass hoàn toàn — tất cả jobs xanh
  7. Merged vào develop

🐛 Khi gặp bug hoặc bị blocked ▼
Khi gặp bug
1️⃣
Bug trong module mình → chạy /debug trong Claude Code, tìm nguyên nhân gốc rễ, fix, viết thêm test để bug không tái phát.
2️⃣
Bug trong module người khác → tạo issue mô tả bug, tag module owner. Không tự sửa dù chỉ 1 dòng.
Khi bị blocked
1️⃣
Chờ leader update contract → comment trên issue, tiếp tục phần UI khác không phụ thuộc vào field đó.
2️⃣
Không hiểu spec → hỏi leader trên issue. Không tự đoán rồi code sai.
3️⃣
WIP limit → tối đa 2 task In Progress cùng lúc. Xong task hiện tại trước khi kéo task mới.
